# Лабораторная работа № 5. Работа с реляционными БД через JdbcTemplate

Вариант 7 — «Военнослужащий».

Работа выполнена доработкой проекта лабораторной № 4 в той же папке `lb4`.

## Цель работы

Заменить JPA на JdbcTemplate в REST-приложении из лабораторной № 4, реализовав доступ к данным через SQL-запросы и преобразование строк БД в Java-объекты. Проверить сохранение и удаление записей, а также работу существующего API.

## Архитектура проекта

- **Стек:** Java 25, Spring Boot 4.1.1, Maven Wrapper, Spring Web MVC, Spring JDBC (`JdbcTemplate`) и Jackson. Для проверки API используется Bruno.
- **СУБД:** H2 в памяти. Адрес подключения — `jdbc:h2:mem:lb4`, пользователь — `sa`, пароль пустой. Таблицы `military_rank` и `serviceman` создаются при запуске из `src/main/resources/schema.sql`. При перезапуске приложения данные сбрасываются.
- **Основные слои:**
  - **Controller:** `MilitaryRankController` и `ServicemanController` принимают HTTP-запросы, проверяют входные данные, вызывают репозитории и возвращают данные для сериализации в JSON. `ApiExceptionHandler` обрабатывает исключения и формирует ответы об ошибках.
  - **Repository:** классы `MilitaryRankRepository` и `ServicemanRepository` отмечены `@Repository` и получают `JdbcTemplate` через конструктор. В их методах явно записаны SQL-запросы; значения передаются через параметры `?`.
  - **Mapper:** классы `MilitaryRankMapper` и `ServicemanMapper` реализуют `RowMapper`. Метод `mapRow()` читает поля строки `ResultSet` и заполняет Java-объект. Данные звания для военнослужащего получаются SQL-соединением `LEFT JOIN` и также заполняются в маппере.
  - **Model:** `MilitaryRank` и `Serviceman` являются обычными Java-классами с полями, геттерами и сеттерами. JPA-аннотации удалены, структура таблиц и внешний ключ определены в `schema.sql`.
  - **DTO:** `ServicemanDTO` принимает данные создания и полного обновления военнослужащего, а также используется как промежуточный объект при частичном обновлении.

**Методы репозиториев**

В обоих репозиториях методы реализованы вручную, как в примерах лабораторной № 5:

| Метод | Реализация |
| --- | --- |
| `findAll()` | `SELECT` через `jdbcTemplate.query()`, возвращающий список объектов |
| `findById(Long id)` | `SELECT ... WHERE id = ?`, возвращающий `Optional` с найденным объектом |
| `save(...)` | `INSERT` через `jdbcTemplate.update()` с `PreparedStatement`; `GeneratedKeyHolder` получает сгенерированный ID, который метод возвращает как `Long` |
| `update(...)` | `UPDATE ... WHERE id = ?` через `jdbcTemplate.update()`, возвращающий количество изменённых строк |
| `deleteById(Long id)` | `DELETE ... WHERE id = ?` через `jdbcTemplate.update()`, возвращающий количество удалённых строк |

| Репозиторий | Дополнительные методы и их назначение |
| --- | --- |
| `MilitaryRankRepository` | `findByName(String name)` — получение звания по названию; `existsByName(String name)` — проверка наличия такого названия |
| `ServicemanRepository` | `findByRankName(String rankName)` — получение военнослужащих выбранного звания; `existsByRankId(Long rankId)` — проверка использования звания |

Дополнительные методы также содержат обычный SQL: поиск выполняется через `query()`, проверки наличия — через `SELECT COUNT(*)` и `queryForObject()`. Автоматической генерации запросов по именам методов больше нет.

- **Ключевые аннотации:**

| Аннотация | Назначение в проекте |
| --- | --- |
| `@SpringBootApplication` | Запуск приложения и автоматическая конфигурация Spring Boot |
| `@Repository` | Регистрация класса доступа к данным как компонента Spring |
| `@JsonIgnore` | Исключение обратной коллекции из JSON для предотвращения циклической сериализации |
| `@RestController`, `@RequestMapping` | Объявление REST-контроллера и общего пути его методов |
| `@GetMapping`, `@PostMapping`, `@PutMapping`, `@PatchMapping`, `@DeleteMapping` | Обработка соответствующих HTTP-методов |
| `@RequestBody` | Преобразование тела JSON-запроса в Java-объект |
| `@PathVariable` | Получение идентификатора из пути запроса |
| `@RequestParam` | Получение необязательного фильтра статистики из параметра запроса |
| `@ResponseStatus` | Установка HTTP-статусов создания, удаления и ошибок |
| `@Transactional` | Выполнение операции изменения данных в одной транзакции |
| `@RestControllerAdvice`, `@ExceptionHandler` | Общая обработка исключений с возвратом JSON-ответов |

- **Описание моделей данных и DTO:**

| Класс | Содержание |
| --- | --- |
| `MilitaryRank` | Идентификатор `id`, уникальное название звания `name` и обратная коллекция `servicemen` |
| `Serviceman` | Идентификатор `id`; фамилия `lastName`, имя `firstName`, отчество `patronymic`; национальность `nationality`; дата рождения `birthDate`; должность `position`; адресные поля `postalCode`, `country`, `region`, `district`, `city`, `street`, `house`, `apartment`; ссылка на звание `rank` |
| `ServicemanDTO` | Входящие данные военнослужащего без `id`. Поле `rank` содержит название звания строкой, по которому контроллер находит связанную сущность |

Между таблицами установлена связь «многие к одному»: несколько военнослужащих могут иметь одно звание. Внешний ключ `serviceman.rank_id` ссылается на `military_rank.id`. Адрес хранится в полях таблицы военнослужащих. В JSON-ответе поле `rank` представлено объектом, например `{"id": 1, "name": "Лейтенант"}`; коллекция `servicemen` исключена из JSON. После удаления JPA-аннотаций эта коллекция больше не загружается автоматически.

Дата рождения передаётся в формате `YYYY-MM-DD` и должна быть в прошлом. Поля `lastName`, `firstName`, `nationality`, `position`, `postalCode`, `country`, `region`, `city`, `street`, `house` и `rank` обязательны. Поля `patronymic`, `district` и `apartment` могут быть пустыми. Проверки выполняются непосредственно в контроллерах.

**Маршруты REST API**

| Метод | Адрес | Назначение |
| --- | --- | --- |
| GET | `/api/ranks` | Список званий |
| GET | `/api/ranks/{id}` | Получение звания по ID |
| POST | `/api/ranks` | Создание звания |
| PUT | `/api/ranks/{id}` | Изменение названия звания |
| DELETE | `/api/ranks/{id}` | Удаление неиспользуемого звания |
| GET | `/api/servicemen` | Список военнослужащих |
| GET | `/api/servicemen/{id}` | Получение военнослужащего по ID |
| POST | `/api/servicemen` | Создание военнослужащего |
| PUT | `/api/servicemen/{id}` | Полное обновление военнослужащего |
| PATCH | `/api/servicemen/{id}` | Частичное обновление военнослужащего |
| DELETE | `/api/servicemen/{id}` | Удаление военнослужащего |
| GET | `/api/servicemen/statistics` | Статистика с необязательным параметром `rank` |

## Алгоритм работы

1. **Запуск приложения.** `Lb4Application` запускает Spring Boot. Создаётся база H2, выполняется `schema.sql`, Spring создаёт `JdbcTemplate` и классы-репозитории. API начинает работу с пустыми таблицами, как в лабораторной № 4.
2. **Создание звания.** Клиент отправляет `POST /api/ranks` с телом `{"name": "Лейтенант"}`. Контроллер проверяет заполненность и уникальность названия через `existsByName()`. Репозиторий выполняет `INSERT` методом `save()` и возвращает новый ID. Контроллер записывает ID в объект и возвращает JSON со статусом `201`.
3. **Создание военнослужащего.** Клиент отправляет `POST /api/servicemen` с личными данными, адресом и названием звания. Jackson преобразует JSON в `ServicemanDTO`. Контроллер проверяет поля и дату рождения, находит звание методом `findByName()` и заполняет объект. Метод `save()` выполняет `INSERT`, записывая ID звания в `rank_id`, и получает ID военнослужащего через `GeneratedKeyHolder`. Контроллер присваивает этот ID объекту и возвращает его со статусом `201`.
4. **Получение данных.** Для списка используется `GET /api/ranks` или `GET /api/servicemen` и метод `findAll()`. Для отдельной записи используется маршрут с `/{id}` и метод `findById()`. Репозиторий выполняет `SELECT`, а `RowMapper` создаёт Java-объекты из строк результата. Jackson преобразует их в JSON. Успешный ответ имеет статус `200`; пустой список возвращается как `[]`.
5. **Полное обновление.** Клиент отправляет `PUT` на маршрут записи с её ID. Контроллер загружает существующий объект, проверяет новые данные, изменяет поля и вызывает `update()`. Репозиторий выполняет SQL `UPDATE`. Идентификатор записи сохраняется; ответ имеет статус `200`.
6. **Частичное обновление.** Клиент отправляет `PATCH /api/servicemen/{id}`, например с телом `{"position": "Командир роты"}`. Контроллер копирует текущие данные в DTO и применяет только переданные поля из `Map<String, Object>`. После проверки всех данных изменения переносятся в объект и сохраняются методом `update()`. Неизвестные поля и некорректные значения отклоняются; при ошибке частичные изменения не сохраняются.
7. **Расчёт статистики.** По `GET /api/servicemen/statistics` контроллер получает всех военнослужащих через `findAll()`. Если передан параметр `rank`, используется `findByRankName()`. Затем рассчитываются количество `totalServicemen`, средний возраст по числу полных лет `averageAge` и распределение по званиям `byRank`. Для пустой выборки возвращаются нулевые количество и средний возраст, а также пустое распределение.
8. **Удаление записи.** При `DELETE` контроллер проверяет существование записи и вызывает `deleteById()`, выполняющий SQL `DELETE`. Перед удалением звания дополнительно проверяется `existsByRankId()`: используемое звание удалить нельзя. Успешное удаление возвращает статус `204` без тела ответа.
9. **Обработка ошибок.** `ApiExceptionHandler` возвращает JSON вида `{"error": "Описание ошибки"}`. Статус `400` означает некорректные данные или JSON, `404` — отсутствие записи или указанного звания, `409` — конфликт уникальности либо попытку удалить используемое звание. Вместо JPA-исключения `EntityNotFoundException` используется исключение Spring JDBC `EmptyResultDataAccessException`.
10. **Проверка API.** В Bruno открывается коллекция из папки `bruno`. Запросы выполняются по номерам: создание звания и военнослужащего, чтение, обновление, статистика, проверки ошибок и удаление записей. Ожидаемый статус указан в названии запроса. В примерах используется ID `1`; фактический ID нужно проверить в ответе создания и при необходимости заменить в следующих URL. При переименовании звания последующие запросы используют новое название.

Для запуска из корня проекта в PowerShell:

```powershell
$env:JAVA_HOME = "C:\Users\Quiet Panic\.jdks\openjdk-25"
.\mvnw.cmd spring-boot:run
```

После запуска API доступен по адресам `http://localhost:8080/api/ranks` и `http://localhost:8080/api/servicemen`. Корневой путь `/` не имеет обработчика и возвращает `404`. Консоль H2 доступна по адресу `http://localhost:8080/h2-console`.

```powershell
.\mvnw.cmd test
```
